# Task: product positioning section for the zonoid README

Write the product positioning section of the zonoid README. Produce a single markdown file at
`bench/sandbox/readme-positioning-ht.md` in the repo `__INSTALL_DIR__`. Do NOT run `git commit`.

## Audience

Senior engineers evaluating AI coding tools. They are skeptical of marketing language. They want
to know: what does this do, how is it different from what I already use, and what are its limits.

## What to produce

A markdown file with the following four parts, in order:

### 1. One-line positioning
A single sentence. It should state what zonoid is and for whom, without using the words
"revolutionary", "powerful", "seamless", or other filler adjectives.
Use the current canonical claim: zonoid is the agent's subconscious for coding work.

### 2. Product description (2 paragraphs)
- Paragraph 1: what the system does in concrete terms — what it stores, when, how agents use it.
- Paragraph 2: the problem it solves and why existing alternatives don't fully solve it.

Keep each paragraph to 3–5 sentences. No bullet lists in this section.

### 3. Key differentiators (3 bullets)
Three specific, verifiable claims about what makes zonoid different from other agent-memory or
context-management tools. Each bullet should be a single sentence that an engineer could
validate by reading the code or running an experiment.

### 4. What it is NOT (scope disclaimer)
3–5 bullets describing things zonoid does not do or is not designed for. This section sets
expectations and prevents misuse. Be direct.

## Tone

Direct, technical, honest. Write as if you are a senior engineer who built this system and wants
another senior engineer to understand it accurately — not to sell it, but to give them the
information they need to decide whether it fits their use case.

Produce the markdown file, then stop.
